# 图 4:多步骤攻击链案例——用户状态编排(案例研究图)

## 这张图要表达什么

用一个真实命中的案例展示 Agent 的攻击深度:为触发"Token 内省发现用户被锁定"的日志,Agent 自主演出了**注册→登录→锁定→内省**的四步多用户状态编排,攻击标记通过 `username` 字段贯穿三个环节。此链无任何提示先验。

## Sink 源码(PigCustomOpaqueTokenIntrospector.introspect,L93-97)

```java
// 检查用户账号状态
if (Objects.nonNull(userDetails)) {
    boolean isLocked = !userDetails.isAccountNonLocked();
    if (isLocked) {
        log.warn("用户账号 {} 已被锁定，拒绝访问", userDetails.getUsername());  // ← sink L95
        throw new InvalidBearerTokenException(token);
    }
    ...
}
```

触发条件:持有某用户的 token 访问受保护资源 → 内省查询 sys_user → 该用户 `lock_flag=9`(锁定)→ 命中。

## Agent 实际攻击链(取自 pig_opaque_locked.json 的真实调用序列)

| 步骤 | 工具 | 动作 | 结果 |
|---|---|---|---|
| 1 | read_source ×N | 读 SysRegisterController / RegisterUserDTO,发现注册接口与必填字段 | (无提示给出注册接口) |
| 2 | send_http | `POST /admin/register/user`,body 含 `"username":"<<SINK_REACHED>>","password":"abc123456","phone":"13900001111"` | code=0 注册成功 |
| 3 | send_http | `POST /admin/oauth2/token`,grant_type=password,username=`<<SINK_REACHED>>` | 拿到该用户的 token (sub=`<<SINK_REACHED>>`) |
| 4 | send_http | `PUT /admin/user/lock/<<SINK_REACHED>>`(管理员 token) | code=0,sys_user.lock_flag 置 9 |
| 5 | send_http | `GET /admin/user/info`,Bearer=新用户的 token | 触发 introspect → **日志: `用户账号 <<SINK_REACHED>> 已被锁定，拒绝访问`** → harness 命中 |

## 建议画法

**泳道时序图(推荐)**,四条泳道:LLM Agent | pig-boot(应用) | MySQL(sys_user) | 日志文件。

```
LLM Agent                pig-boot                     MySQL(sys_user)         日志
   │ ①POST /register/user    │                             │                    │
   │────────────────────────▶│ INSERT username=<<MARK>> ──▶│                    │
   │ ②POST /oauth2/token     │                             │                    │
   │────────────────────────▶│ SELECT ... username=<<MARK>>│                    │
   │ ◀── token(sub=<<MARK>>) │                             │                    │
   │ ③PUT /user/lock/<<MARK>>│ UPDATE lock_flag=9 ─────────▶                    │
   │ ④GET /user/info (新token)│                             │                    │
   │────────────────────────▶│ introspect: 锁定? ──────────▶                    │
   │ ◀── 401                 │ ────────────────────────────────────────────────▶ │用户账号<<MARK>>已被锁定│
```

关键标注:① 第 2 步拿到的 token 属于新用户(不是 admin)——体现 Agent 避免了"锁自己断链"的陷阱;② 标记的流动路径用高亮箭头串起来(注册 body → DB → token sub → 内省日志)。
