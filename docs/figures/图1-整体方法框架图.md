# 图 1:整体方法框架图(必画,论文 Figure 1)

## 这张图要表达什么

两阶段方法总览:阶段一(静态)从源码提取 sink 并用 LLM 分类出"黑盒不可 fuzz"的目标池;阶段二(动态)LLM Agent 用 8 个工具自主构造前置状态并触发 sink,由 harness 用日志标记判定命中。

## 建议画法

横向三列的框架图(用 drawio / PPT / mermaid 均可):

```
┌───────────── 阶段一: 静态分析 ─────────────┐   ┌──────────── 阶段二: LLM Agent 动态利用 ────────────┐
│                                             │   │                                                      │
│  Java 微服务源码                             │   │   任务: sink 位置 + 日志模板 (+部署事实, hint 档)      │
│      │                                      │   │        │                                             │
│      ▼                                      │   │        ▼                                             │
│  [Sink 提取器]                               │   │   ┌─────────────── LLM Agent 循环 ───────────────┐   │
│  日志调用/异常处理器/AOP 切面                  │   │   │ ① read_source 读 sink 分支条件                │   │
│      │ 2230 个 sink                          │   │   │ ② query_db / redis_cmd 诊断缺失状态           │   │
│      ▼                                       │   │   │ ③ 规划业务 API 序列构造前置 (send_http)       │   │
│  [LLM 黑盒可达性分类]                         │   │   │ ④ 触发请求                                   │   │
│  ├─ HTTP 可达 1277                           │   │   │ ⑤ read_logs 看执行到哪个分支 (偏差反馈)       │   │
│  │    ├─ 黑盒可 fuzz 196 → 对照池             │   │   │ ⑥ 未命中 → 修正后重试                        │   │
│  │    └─ 黑盒不可 fuzz 1081 → 目标池 ─────────┼──▶│   └──────────────────────┬────────────────────┘   │
│  └─ HTTP 不可达 937 (定时任务/框架内部)        │   │                          │                        │
│                                             │   │                          ▼                        │
│  附: [API→表映射] Joern+MyBatis ─────────────┼──▶│   [harness 命中判定] 目标日志中标记基线增量          │
└─────────────────────────────────────────────┘   └──────────────────────────────────────────────────────┘
```

## 图中必须出现的元素

- 两个池的划分及数字(196 / 1081)
- Agent 循环的 6 步(标注 8 个工具分别在哪几步使用)
- harness 判定框(强调"不信任 Agent 自述,以日志标记基线增量为准")
- 目标系统侧可以画一个小框:目标微服务 + MySQL + Redis(表示 Agent 作用的外部环境)

## 配色建议

阶段一用蓝色系,阶段二用橙色系,harness 判定用绿色,命中/未命中分支用实线/虚线区分。
